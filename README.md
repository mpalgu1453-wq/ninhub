# Nintendo Stock Manager (Supabase)

ระบบจัดการสินค้า Nintendo Switch แบบออนไลน์ มีล็อกอิน, สิทธิ์แอดมิน/พนักงาน, เก็บข้อมูลใน Supabase (ฟรี)

## โครงสร้างไฟล์

- `index.html` — แอปหลัก (ล็อกอิน + จัดการคลังสินค้า รับเข้า/ขาย/โอน Excel รายงาน)
- `js/config.js` — ใส่ URL และ anon key ของ Supabase
- `supabase/schema.sql` — ตาราง + สิทธิ์ + ฟังก์ชันบันทึกสต๊อก
- `supabase/upgrade-auto-create.sql` — อัปเกรดฐานข้อมูลเดิมให้รองรับ "สร้างสินค้าใหม่อัตโนมัติ" (วางใน SQL Editor แล้ว Run ได้เลย ไม่ลบข้อมูลเดิม)
- `supabase/cancel-bill.sql` — เปิดใช้ฟังก์ชันยกเลิกบิลขายภายใน 24 ชม.
- `supabase/storage-images.sql` — เปิดใช้ Supabase Storage สำหรับเก็บรูปสินค้าและสร้างลิงก์รูป
- `supabase/public-catalog.sql` — เปิดแคตตาล็อกสำหรับลูกค้า (ดูสินค้าได้โดยไม่ต้องล็อกอิน) + ตารางส่วนลดรายสินค้าตามช่วงวันที่

## ขั้นตอนตั้งค่า (ครั้งแรก)

### 1. สร้างโปรเจกต์ Supabase (ฟรี)

1. ไปที่ https://supabase.com → สมัครบัญชี → **New Project**
2. ตั้งชื่อโปรเจกต์ เชื่อ region `Southeast Asia (Singapore)` เพื่อความเร็ว
3. ตั้งรหัสฐานข้อมูล (เก็บไว้)

### 2. รัน schema

1. ใน Supabase Dashboard เลือก **SQL Editor** → **New query**
2. เปิดไฟล์ `supabase/schema.sql` คัดลอกทั้งหมดวางลงไป → กด **Run**
3. ตรวจสอบว่าไม่มี error (มีข้อความ success)
4. รันซ้ำได้เสมอ (idempotent) — ถ้าเคยรันเวอร์ชันเก่า ให้วางไฟล์ใหม่ทับแล้ว Run อีกครั้งเพื่ออัปเดตสิทธิ์/ฟังก์ชัน

> หมายเหตุด้านความปลอดภัย: ระบบบังคับที่ database ระดับ RLS — **การบันทึกเคลื่อนไหว (รับเข้า/ขาย/โอน), ปรับยอดตรวจนับ, นำเข้า Excel และเพิ่ม/แก้ไข/ลบสินค้า เป็นสิทธิ์แอดมินคนเดียว** พนักงานดูและส่งออกได้อย่างเดียว

## การออกจากระบบอัตโนมัติ

- **ปิดเบราว์เซอร์/แท็บแล้วเปิดใหม่ → ยังล็อกอินอยู่** (ไม่ต้องเข้าสู่ระบบใหม่ จนกว่าจะกด “ออกจากระบบ” หรือไม่ใช้งานเกิน 5 ชั่วโมง)
- **ไม่มีการใช้งานเกิน 5 ชั่วโมง → ออกจากระบบอัตโนมัติ** และกลับไปหน้าล็อกอิน (นับจากการขยับเมาส์/พิมพ์/แตะ/เลื่อนหน้าจอ; ถ้าเปิดหลายแท็บจะนับรวมกัน)

### 3. เปิดใช้ Realtime (ให้หลายอุปกรณ์อัปเดตพร้อมกัน)

1. ไปที่ **Database** → **Replications**
2. เปิดตาราง `products` และ `moves` (toggle ON)

### 4. ใส่ค่า Supabase ในแอป

1. ไปที่ **Project Settings** → **API** (หรือ **Data API**)
2. คัดลอก **Project URL** และ **anon public key**
3. เปิดไฟล์ `js/config.js` ใส่ค่า:
   ```js
   window.SUPABASE_URL = 'https://xxxx.supabase.co';
   window.SUPABASE_ANON_KEY = 'eyJhbGciOi...';
   ```

### 5. ปิดการยืนยันอีเมล (สำหรับทดสอบง่าย ๆ)

1. ไปที่ **Authentication** → **Sign In / Providers** → **Email**
2. ปิด **Confirm email** (หรือจะเปิดไว้ก็ได้ แล้วกดยืนยันจากอีเมลจริง)

### 6. สมัครสมาชิกและตั้งตัวเองเป็นแอดมิน

1. เปิด `index.html` ในเบราว์เซอร์ (หรือรัน `npx serve` ในโฟลเดอร์นี้)
2. กด **ยังไม่มีบัญชี? สมัครสมาชิก** → ใส่อีเมล+รหัสผ่าน
3. หลังสมัคร กลับไป Supabase → **SQL Editor** รัน:
   ```sql
   update public.profiles set role = 'admin' where email = 'YOUR_EMAIL@example.com';
   ```
4. ออกจากระบบแล้วเข้าใหม่ → ตอนนี้เป็นแอดมินแล้ว

## การจัดการคลังสินค้า

- **การ์ด “⚠️ สินค้าใกล้หมด” กดได้** — แสดงจำนวนแยก “เหลือ 0” กับ “เหลือ 1–3” และเมื่อกดจะเปิดหน้าคลังสินค้าที่กรองเฉพาะสินค้าใกล้หมด **เรียงจากน้อยไปมาก (ของที่หมด/ติดลบขึ้นก่อน)** พร้อมคอลัมน์ “คงเหลือ” และป้ายสีแดงสำหรับของที่หมดแล้ว — มีปุ่ม **⚠️ ใกล้หมด** ไว้เปิด/ปิดตัวกรองเอง
- **กราฟสินค้าขายดี** — หน้าภาพรวมมีกราฟแท่ง “🏆 สินค้าขายดี” 10 อันดับแรก สลับดูได้ **วันนี้ / เดือนนี้ / ปีนี้** พร้อมยอดขาย (ชิ้น) และมูลค่ารวมของช่วงนั้น (นับเฉพาะรายการ “ขายออก”) — กด **⬇ Excel** เพื่อส่งออกรายการขายดีทั้งหมดของช่วงที่เลือก (อันดับ รหัส ชื่อ จำนวน ยอดขาย และแถวรวม) เป็นไฟล์ `.xlsx`
- **เลือกหลายรายการ** (ติ๊กช่องหน้าตาราง) แล้วกด **📁 ย้ายหมวดหมู่** เพื่อย้ายสินค้าที่เลือกไปหมวดที่ต้องการพร้อมกัน หรือกด **🗑 ลบที่เลือก** เพื่อลบทั้งชุด
- **แบ่งหน้า** — เลือก “แสดงต่อหน้า” 20 / 50 / 100 / ทั้งหมด หรือกดเลขหน้า / ก่อนหน้า–ถัดไป ใต้ตาราง (ค่าเริ่มต้น 50 รายการ)
- **สแกนหาสินค้า** — กดปุ่ม **▦ สแกน** มุมขวาบน ระบบจะเปิดกล้องแล้วค้นหาสินค้าจากบาร์โค้ดให้ทันที (เปิดหน้ารายละเอียดให้) หรือใช้เครื่องสแกนยิงเข้าช่องค้นหาแล้วกด Enter ก็ได้
- ช่อง “เลือกทั้งหมด” จะเลือกเฉพาะรายการในหน้านี้

## การรับสินค้าเข้า / โอนออก

เมนู **⇄ รับเข้า / โอน** ใช้สำหรับบันทึกของเข้าและโอนออกให้ร้านอื่น (แยกจากหน้าขายแล้ว)

1. เลือกแท็บ **รับสินค้าเข้า** หรือ **โอนให้ร้านอื่น** (ช่อง “ร้านปลายทาง” จะแสดงเฉพาะตอนโอน)
2. สแกน/พิมพ์รหัส หรือเลือกสินค้า ใส่จำนวนและราคา แล้วกด **บันทึกการโอน / บันทึกรับเข้า**
3. ระบบตรวจยอดคงเหลือก่อนโอนออก และบันทึกการเคลื่อนไหวลงฐานข้อมูลออนไลน์

## การขายหลายรายการในบิลเดียว

1. ไปที่เมนู **🧾 ขายสินค้า** (แยกหน้าจากรับเข้า/โอน)
2. สแกน/พิมพ์รหัสหรือเลือกสินค้า ใส่จำนวนและราคา แล้วกด **＋ เพิ่มลงบิล** (ทำซ้ำได้หลายรายการ)
3. ตรวจรายการในบิล (รหัสซ้ำจะรวมจำนวนให้อัตโนมัติ) แล้วกด **💾 บันทึกบิล** — ระบบจะตัดสต๊อกทุกรายการพร้อมกันในครั้งเดียว
4. หลังบันทึกบิลจะเคลียร์รายการให้เริ่มบิลใหม่ทันที (บิลก่อนหน้าถูกเก็บไว้แล้ว)
5. ตาราง **บิลขายล่าสุด** ด้านล่างแสดงเลขบิล จำนวนรายการ ชิ้น และยอดรวม — กด **ดู** เพื่อเปิดรายละเอียดว่าบิลนั้นขายอะไรไปบ้าง
6. **ยกเลิกบิลได้ภายใน 24 ชั่วโมง** (เฉพาะแอดมิน) — กดปุ่ม **ยกเลิก** ในตารางหรือในหน้าต่างรายละเอียดบิล ระบบจะคืนจำนวนสินค้าเข้าคลังและลบรายการขายของบิลนั้นออกจากประวัติ (เกิน 24 ชม. ปุ่มจะหายไป และเซิร์ฟเวอร์ก็ปฏิเสธ)

> การขายหนึ่งครั้งได้เลขบิล (`bill_id`) เดียวกันทุกรายการ และประวัติ/ไฟล์ส่งออก Excel มีคอลัมน์ **เลขบิล** ให้ด้วย รายการขายเก่าก่อนอัปเดตจะแสดงเป็น “บิลเดี่ยว”
> ต้องรัน `supabase/upgrade-auto-create.sql` อีกครั้งเพื่อเพิ่มคอลัมน์ `bill_id` และฟังก์ชัน `record_bill`
> ต้องรัน `supabase/cancel-bill.sql` หนึ่งครั้งเพื่อเปิดใช้ฟังก์ชัน `cancel_sale` (ยกเลิกบิล)

## การนำเข้าข้อมูล (ไฟล์ Excel)

**รหัสที่ยังไม่มีในคลังจะถูกสร้างสินค้าใหม่อัตโนมัติในหมวด “ไม่มีหมวดหมู่” เสมอ** (เฉพาะสิทธิ์แอดมิน) และจะมีหน้าตารางยืนยันให้ตรวจสอบก่อนทุกครั้ง

พฤติกรรมเมื่อยืนยันนำเข้า:

- **โหมดค่าเริ่มต้น: ตั้งยอดคงเหลือตามจำนวนในไฟล์** → จำนวนคงเหลือจะเท่ากับจำนวนในไฟล์ทันที (ไม่บวกกับยอดเดิม) ถ้าจำนวนในไฟล์มากกว่าจะเพิ่มยอด ถ้าน้อยกว่าจะลดยอด และบันทึก movement `ตรวจนับ` ให้ตรวจย้อนหลังได้
- **สินค้าใหม่ (รหัสยังไม่มีในระบบ)** → สร้างในหมวด `ไม่มีหมวดหมู่` พร้อมจำนวน/บาร์โค้ด/ราคาจากไฟล์ แล้วค่อยย้ายหมวดทีหลังได้
- **อัปเดตเฉพาะบาร์โค้ด/ราคา** → โหมดสำหรับเติมบาร์โค้ดให้สินค้าเดิมโดยไม่แตะจำนวนสต๊อก (ใช้เมื่อบาร์โค้ดในระบบยังว่าง)
- **บวกจำนวนเพิ่มเข้าสต๊อก** → ตัวเลือกเสริม ใช้เฉพาะกรณีต้องการเพิ่มของใหม่เข้าคลัง (ยอดเดิม + จำนวนในไฟล์) ไม่ใช่การตั้งยอดตามไฟล์
- **เก็บเป็นรายงานตรวจนับ** → ไม่เปลี่ยนสต๊อก ใช้ดูผลต่างระหว่างไฟล์กับระบบเท่านั้น

> ไฟล์ Excel ของบริษัท (`PRNDATE | SKCODE | IBC | SBC | PRNAME | QUANT | RETAIL`) ใช้ได้โดยตรง: รหัสสินค้า = `SKCODE`, บาร์โค้ด = `SBC` ถ้าว่างจะใช้ `IBC` แทน, จำนวน = `QUANT`, ราคา = `RETAIL`

> ถ้าเคยรันสคริปต์เวอร์ชันเก่าไว้ ให้รัน `supabase/upgrade-auto-create.sql` อีกครั้ง (Supabase → SQL Editor → วางทั้งไฟล์ → Run)
> เพื่ออัปเดตฟังก์ชัน `apply_stock_count` ให้สร้างสินค้าใหม่ + บันทึก movement ได้ครบทุกโหมด
> ไฟล์นี้ยังย้ายสินค้าที่มีชื่อหมวดหมู่นอกเหนือจากรายการหลัก (เช่น `เครื่อง`, `JOY&ACC` ที่ติดมาจาก Excel) ไปเป็น `ไม่มีหมวดหมู่` ให้ด้วย

### นำเข้าไฟล์ Excel

1. ไปที่หน้า **Excel นำเข้า–ส่งออก**
2. อัปโหลดไฟล์ `.xlsx` / `.xls` / `.csv`
3. ระบบจะหาแถวหัวตารางและคอลัมน์ **รหัสสินค้า** + **จำนวน** ให้เอง (รองรับหัวตารางไทย/อังกฤษ, มีแถวหัวเรื่องนำหน้า, จำนวนเป็นข้อความมีหน่วย เช่น `10 ชิ้น` หรือมีคอมม่า `1,250`)
4. ตรวจสอบตาราง "สถานะ" แล้วกด **ยืนยันนำเข้าข้อมูล**

ชื่อสินค้า / **บาร์โค้ด** / **ราคา** ใส่ได้ถ้ามี (ไม่บังคับ) และจะถูกบันทึกเข้าคลังให้อัตโนมัติ — คอลัมน์หมวดหมู่ในไฟล์จะไม่ถูกใช้ (สินค้าใหม่ลง `ไม่มีหมวดหมู่` เสมอ)

**รองรับรายงาน POS โดยตรง** — ถ้าหัวตารางเป็น
`PRNDATE | SKCODE (SBC) | PRNAME | QUANT | RETAIL` ระบบจะจับคอลัมน์ถูกเอง
(คอลัมน์ `SKCODE`/`SBC` → รหัสสินค้า, `PRNAME` → ชื่อ, `QUANT` → จำนวน, `SBC`/บาร์โค้ด → บาร์โค้ด, `RETAIL`/ราคา → ราคา/ต้นทุนต่อชิ้น)
แถวตัวอย่าง: `17/10/2026 19:55:10 | 306200 | 4902370553208 | NS-JOY-CON2 NINTENDO-WHEEL-SET | 1.00 | 790.00`

> คอลัมน์บาร์โค้ดต้องมีค่าเต็ม 13 หลัก ถ้าใน Excel แสดงเป็น `4.90237E+12` ให้ขยายคอลัมน์/ตั้งรูปแบบเป็น Text ก่อนบันทึก ไม่งั้นตัวเลขจะถูกปัดหาย
> ตัวอ่านไฟล์ Excel ( SheetJS ) จะโหลดเมื่อเปิดเมนู **Excel นำเข้า–ส่งออก** ครั้งแรก ไม่ถ่วงเวลาเข้าสู่ระบบ

กฎความปลอดภัยของตัวนำเข้า:

- **จำนวนต้องเป็นจำนวนเต็ม ≥ 0** — ถ้าเป็นทศนิยม (เช่น `1.50`) จะขึ้นสถานะ `จำนวนต้องเป็นจำนวนเต็ม` และบล็อกการนำเข้าจนกว่าจะแก้
- รหัสซ้ำในไฟล์เดียวกัน → บล็อกการนำเข้า
- จำนวนที่ผิดปกติ (เช่น > 999,999 ซึ่งน่าจะเป็นบาร์โค้ดที่อ่านเพี้ยน) → ขึ้นสถานะ `จำนวนผิดปกติ` และบล็อกการนำเข้า
- จำนวนที่มีเครื่องหมายคอมม่า หรือสูงผิดปกติ → ขึ้นป้าย `ควรตรวจสอบ` (ไม่บล็อก แต่ให้เช็กก่อนยืนยัน)
- ถ้าไฟล์ไม่มีคอลัมน์รหัสสินค้า ระบบจะหาสินค้าในคลังจาก **ชื่อสินค้า** ให้อัตโนมัติ (ต้องให้ชื่อตรงกับข้อมูลในระบบ) แล้วขึ้นป้าย `จับคู่จากชื่อสินค้า`

### ส่งออก Excel

เลือก “ชนิดข้อมูล” ได้: **สินค้าคงเหลือปัจจุบัน**, **ประวัติรับเข้า–ขาย–โอน** (ทั้งหมด — ตัวเลือกเดิม), หรือแยกเป็น **ประวัติรับเข้า**, **ประวัติขาย**, **ประวัติโอน** ตามหมวดหมู่ที่เลือก

## รูปสินค้า: อัปโหลด / ใช้ลิงก์

- **แนะนำ: อัปโหลดรูปจากอุปกรณ์** — ระบบย่อรูปให้อัตโนมัติ (ด้านยาวสุดไม่เกิน 600 px, JPEG) แล้วเก็บไฟล์จริงใน **Supabase Storage** (bucket `product-images`) และเก็บแค่ลิงก์ในฐานข้อมูล ทำให้ฐานข้อมูลเบาและนำลิงก์ไปใช้ต่อได้
  - ต้องรัน `supabase/storage-images.sql` ครั้งเดียวใน Supabase → SQL Editor
  - รูปจะได้ลิงก์ถาวรแบบ `https://<project>.supabase.co/storage/v1/object/public/product-images/<รหัส>/<เวลา>.jpg`
  - ถ้ายังไม่ได้รัน SQL ระบบจะยังบันทึกรูปฝังในฐานข้อมูลให้ชั่วคราว พร้อมแจ้งเตือน
- **ใช้ลิงก์จากเว็บอื่น** — ต้องเป็น **ลิงก์รูปโดยตรง** (เช่น ลงท้าย `.jpg` `.png` `.webp` หรือเป็น CDN ที่ส่งไฟล์รูปจริง) ไม่ใช่ลิงก์หน้าสินค้า/หน้าแชร์
  - **Google Drive**: แชร์ไฟล์เป็น **“ทุกคนที่มีลิงก์”** → คัดลอกลิงก์ → วางในช่องลิงก์ได้เลย ระบบแปลงเป็นลิงก์รูปให้อัตโนมัติ (รูปแบบ `https://lh3.googleusercontent.com/d/<id>=w1200`)
  - **Dropbox**: คัดลอกลิงก์แชร์ (ลงท้าย `?dl=0`) มาวาง ระบบเปลี่ยนเป็น `?raw=1` ให้เอง
  - เว็บจำนวนมาก (Powerbuy, Shopee, Lazada, Facebook, Google Photos) **ไม่อนุญาตให้เว็บอื่นฝังรูป** — รูปจะไม่ขึ้นและฟอร์มจะแจ้ง “ลิงก์นี้แสดงรูปไม่ได้”
  - วิธีเอา **ลิงก์รูปโดยตรง** จากเว็บอื่น: เปิดหน้าสินค้า → คลิกขวาที่รูป → **คัดลอกที่อยู่รูปภาพ / Copy image address** (มือถือ: กดค้างที่รูป → ดาวน์โหลด/แชร์ลิงก์รูป) แล้วนำมาวางในช่องลิงก์
  - ถ้าคัดลอกมาแล้วยังไม่ขึ้น ให้ **ดาวน์โหลดรูปเก็บไว้ในเครื่อง** แล้วใช้ช่อง **อัปโหลดรูปจากอุปกรณ์** แทน (วิธีนี้เสถียรที่สุด)
- **หมายเหตุ Google Drive**: ใช้ได้กับรูปจำนวนไม่มากและไฟล์ต้องแชร์สาธารณะ ถ้ามีคนเปิดพร้อมกันเยอะ Google อาจจำกัดการแสดงรูป (ขึ้นรูปเสีย) — แนะนำใช้ **Supabase Storage** ผ่านช่องอัปโหลดในฟอร์มสินค้าแทน
- หลังบันทึกรูปขึ้น Supabase Storage แล้ว เปิดสินค้า → กด **“คัดลอกลิงก์รูป”** เพื่อนำลิงก์ไปใช้กับเว็บ/แชทอื่นได้
- ฟอร์มเพิ่ม/แก้ไขสินค้ามี **ตัวอย่างรูป** แสดงทันที และตอนกดบันทึกระบบจะ **ทดลองโหลดลิงก์จริง** — ถ้าโหลดไม่ได้จะมีคำถามว่าจะบันทึกโดยไม่ใช้ลิงก์นี้หรือกลับไปแก้ไข

## แคตตาล็อกสำหรับลูกค้า (ในเว็บสต๊อก)

- เปิดใช้ครั้งแรก: Supabase → **SQL Editor** → รันไฟล์ `supabase/public-catalog.sql`
- **เว็บลูกค้าจริงแยกอยู่ที่ repo `ninhub-shop`** (เช่น `https://ninhub-shop.vercel.app`) — ปุ่ม “ดูสินค้าสำหรับลูกค้า” ที่หน้าเข้าสู่ระบบถูกเอาออกแล้ว
- แอดมินยังเปิดดูหน้าร้านในเว็บสต๊อกได้จากเมนู **🛍️ หน้าร้านลูกค้า** → หน้าร้านสไตล์ Nintendo มีหัวเว็บสีแดง, แบนเนอร์ Switch 2, การ์ดหมวดหมู่ 4 หมวด (เครื่องเกม / ตุ๊กตา / จอยเกม/ACC / แผ่นเกม), ส่วน **สินค้าขายดี** และกริดสินค้าทั้งหมด พร้อมค้นหาและกรองหมวดหมู่
- แสดง **ชื่อ / หมวดหมู่ / ราคาขาย / สถานะ** (พร้อมจำหน่าย · เหลือน้อย · สินค้าหมด) / **จำนวนคงเหลือ** และรูป — ไม่มีต้นทุนหรือบาร์โค้ด
- **กดที่การ์ดสินค้า** หรือปุ่ม **🛒 จอง** เพื่อเปิดรายละเอียด (รูปใหญ่ ราคา สถานะ จำนวนคงเหลือ) — ปิดด้วยปุ่ม “ปิด ✕”, ปุ่ม Esc หรือกดพื้นหลัง
- **ปุ่มหัวใจ ♡** บันทึกสินค้าที่ถูกใจไว้ในเบราว์เซอร์ (`localStorage` key `ninhub_catalog_favs`) — ไม่ต้องล็อกอิน และไม่เปิดหน้าต่างสินค้า
- ปุ่ม **ดูทั้งหมด** ในส่วนสินค้าขายดีจะเลื่อนไปยังกริดสินค้าทั้งหมด และเมนู ☰ ด้านขวาบนใช้ข้ามหมวดหมู่/กลับเข้าสู่ระบบได้
- **แอดมินเปลี่ยน/เพิ่มรูปสินค้าได้จากหน้าร้าน:** เข้าหลังบ้าน → เมนู **🛍️ หน้าร้านลูกค้า** (หรือคลังสินค้า → **🖼️ จัดการรูป**) → กด **🖼️ จัดการรูป** ที่หัวเว็บ → ค้นหาสินค้า → **⬆ อัปโหลด** รูปจากอุปกรณ์, **🔗 ลิงก์** รูปจากเว็บ หรือ **ลบรูป** — รูปจะอัปเดตขึ้นแคตตาล็อกทันที (hero/หมวดหมู่ใช้รูปสินค้าจากหมวดนั้นอัตโนมัติ)
- หน้าร้านปรับ **สัดส่วนสำหรับโทรศัพท์** แล้ว: hero กะทัดรัด, การ์ดหมวดหมู่ 2×2, สินค้า 2 คอลัมน์, รูปสินค้าเป็นสัดส่วน 4:3, ราคาและปุ่ม **จอง** เต็มความกว้าง อ่านง่าย ไม่ล้นจอ
- ราคาที่แสดงคือช่อง **“ราคาขายหน้าร้าน”** ในฟอร์มสินค้า (แอดมินตั้งค่า) — ถ้ายังไม่ได้ตั้งราคาขาย ระบบจะใช้ **ราคาที่นำเข้า/ต้นทุนที่บันทึกไว้** แสดงแทน และถ้าเป็น 0 ทั้งคู่จะแสดง “สอบถามราคา”
- ราคาและส่วนลดจะ **อัปเดตอัตโนมัติ** เมื่อกลับมาที่หน้าแคตตาล็อก (สลับแท็บ/โฟกัสหน้าต่าง) และรีเฟรชทุก 60 วินาทีขณะเปิดหน้าไว้ — ไม่ต้องโหลดหน้าใหม่
- **ส่วนลดรายสินค้า:** แอดมินตั้งได้ที่เมนู **🏷️ ส่วนลด** → เลือกสินค้า, ประเภท (เปอร์เซ็นต์/จำนวนเงิน), มูลค่า และ **ช่วงวันที่เริ่ม–สิ้นสุด**
  - **มูลค่าส่วนลด** คือจำนวนที่ต้องการลดจริง: แบบ % จะลดตามเปอร์เซ็นต์, แบบจำนวนเงินจะลดเป็นบาท (เช่น ราคา 1,000 ลด 500 → ลูกค้าเห็น 500)
  - ฟอร์มมีช่อง **ราคาปกติ / ราคาขายหน้าร้าน** — ระบบ **ดึงราคาจากสินค้าให้อัตโนมัติเมื่อเลือกสินค้า** (ถ้ายังไม่ได้ตั้งราคาขาย จะใช้ราคาที่นำเข้า/ต้นทุนที่บันทึกไว้ก่อน) และแก้ไขได้ — บันทึกแล้วระบบจะอัปเดตราคาสินค้าให้ด้วย
  - หรือใส่ **ราคาหลังลด** โดยตรง เช่น ราคาปกติ 2,900 ใส่ราคาหลังลด 2,500 → ระบบคำนวณส่วนลดเป็นเงิน 400 บาท (13.79%) ให้อัตโนมัติ และเติมช่องมูลค่าส่วนลดให้ พร้อมแสดงตัวอย่างราคาที่ลูกค้าจะเห็น
  - ถึงวันเริ่ม ส่วนลดจะขึ้นบนแคตตาล็อกลูกค้าอัตโนมัติ: ราคาปกติขีดฆ่า + ราคาลด + ป้าย `-10%` / `-฿500`
  - หน้ารายละเอียดสินค้าของลูกค้าจะแสดงข้อความส่วนลดและวันหมดโปร
  - ตั้งได้หลายรายการต่อสินค้า — ระบบเลือกส่วนลดที่ทำให้ราคาถูกที่สุดของวันนั้น
  - แก้ไข/ลบ/ปิดใช้งานได้ในหน้าเดียวกัน และเปลี่ยนวันที่มีผลได้ตลอด
  - หน้า **ขายสินค้า** จะเติมราคาหลังลดให้อัตโนมัติเมื่อสินค้ามีโปรวันนี้ พร้อมข้อความแจ้งส่วนลด
  - ในฟอร์มเพิ่ม/แก้ไข: **พิมพ์รหัส/บาร์โค้ดหรือชื่อสินค้า** แล้วรายการจะกรองให้เห็นทันที — กด **Enter** หรือปุ่ม **ค้นหา** เพื่อเลือกสินค้าที่ตรงกัน และมี **ตัวกรองหมวดหมู่** — รายการสินค้าจัดกลุ่มตามหมวดหมู่ให้เลือกง่าย
- ถ้าเพิ่งอัปเดตเวอร์ชันนี้ ต้อง **รัน `supabase/public-catalog.sql` ซ้ำ** เพื่ออัปเดตฟังก์ชัน `public_catalog()` ให้ดึงราคาที่นำเข้า/ต้นทุนมาแสดงเมื่อยังไม่ได้ตั้งราคาขาย (และเพิ่มคอลัมน์ราคา/ตาราง `discounts` หากยังไม่มี)
- รูปที่จะแสดงต้องเป็นลิงก์ `https://` (รูปที่อัปโหลดผ่านฟอร์มสินค้า) — รูปเก่าที่ฝัง base64 จะขึ้นเป็นไอคอน 🎮
- การเปิดแคตตาล็อกจะโหลดรูปจาก Supabase (นับ Egress) — ระบบโหลดเฉพาะการ์ดที่เลื่อนมาเห็นและรูปถูกย่อ 600 px แล้ว
- ปิดการใช้งานชั่วคราว: `revoke execute on function public.public_catalog() from anon;`

## ลดปริมาณการใช้งาน Supabase (Free plan)

โควตาฟรีที่มักเต็มก่อน: **Egress 5 GB/เดือน** และ **Database 500 MB** (รูปเก่าที่บันทึกไว้ก่อนอัปเดตยังเก็บเป็น base64 ในฐานข้อมูล)

สิ่งที่ปรับไว้ให้แล้ว:

- **รูปย่ออัตโนมัติก่อนบันทึก** — ย่อด้านยาวสุดไม่เกิน 600 px เป็น JPEG แล้วอัปโหลดขึ้น Supabase Storage (เก็บแค่ลิงก์ในฐานข้อมูล) รับไฟล์ได้ไม่เกิน 8 MB
- **ไม่โหลดรูปทั้งคลังตอนเข้าเว็บ** — แกลเลอรีโหลดรูปเฉพาะการ์ดที่เลื่อนมาเห็น (IntersectionObserver) และรวมคำขอเป็นชุด (batched)
- **แคชรูปในเครื่อง (IndexedDB)** — เปิดรูปเดิมซ้ำในเครื่อง/เบราว์เซอร์เดิม = โหลดจากเครื่อง ไม่กิน egress และตัดแคชอัตโนมัติเมื่อแก้รูป (อิง `updated_at`)
- **ประวัติเคลื่อนไหวโหลดแค่ 200 รายการล่าสุด** และเฉพาะคอลัมน์ที่ใช้ (จากเดิม 500 แถวทั้งตาราง)
- **แคตตาล็อก** จะโหลดรูปของหมวดที่เลือกครั้งเดียวตอนสั่งพิมพ์ และมีคำเตือนถ้าเกิน 40 รายการ — ใช้เมื่อจำเป็นเท่านั้น
- **บีบอัดรูปเก่าทั้งคลัง (เฉพาะแอดมิน)** — เมนูด้านซ้าย “🧹 บีบอัดรูป” กดครั้งเดียวระบบจะย่อรูปเดิมทีละชุดแล้วบันทึกทับด้วยรูป 640 px / คุณภาพ 0.6 พร้อมแจ้งความคืบหน้าและสรุปขนาดก่อน–หลัง (แนะนำให้รันหนึ่งครั้งหลังอัปเดตระบบ)

คำแนะนำเพิ่มเติม:

- หลีกเลี่ยงการอัปโหลดรูปความละเอียดสูงซ้ำ ๆ ระบบย่อให้แล้ว — รูปเก่าที่เคยบันทึกไว้ให้ใช้การ์ด “บีบอัดรูปสินค้าเก่า” (กินเน็ตครั้งเดียวตอนรัน แต่ลดขนาดถาวร) หรือลบ/เปลี่ยนรูปที่ไม่ใช้
- Egress นับเฉพาะข้อมูลที่โหลดผ่านอินเทอร์เน็ต (รวมรูปที่เปิดดู) — ถ้าเดือนไหนใกล้เต็ม ให้ลดการเปิดแคตตาล็อก/แกลเลอรีรูปจำนวนมาก
- ดูขนาดรูปที่เก็บอยู่ได้ด้วย SQL:
  ```sql
  select count(*) filter (where image <> '') as with_image,
         pg_size_pretty(sum(pg_column_size(image))::bigint) as total_image,
         pg_size_pretty((avg(pg_column_size(image)) filter (where image <> ''))::bigint) as avg_image
  from public.products;
  ```
- โควตาจะรีเซ็ตรอบบิลรายเดือนใน Supabase → Settings → Billing

ไม่ต้องเขียน backend เพิ่ม Supabase ทำหน้าที่เป็น backend ให้แล้ว

## ข้อควรระวัง

- `SUPABASE_ANON_KEY` เป็นของสาธารณะ (ปลอดภัยที่จะใส่ในหน้าเว็บ) เพราะ RLS จะตรวจสิทธิ์ทุกครั้ง
- **ห้าม** ใช้ `service_role` key ในหน้าเว็บเด็ดขาด
- ถ้าเปลี่ยนรหัสผ่าน Supabase หรือลบโปรเจกต์ ต้องอัปเดต `js/config.js` ใหม่

## แยกเว็บลูกค้า (repo: ninhub-shop) + ระบบจอง

repo นี้คือ **เว็บสต๊อก/หลังบ้าน** ส่วนเว็บลูกค้าแยกเป็นอีก repo หนึ่ง แต่ใช้ **Supabase โปรเจกต์เดียวกัน** ข้อมูลสินค้า/ราคา/ส่วนลด/รูป/การจอง จึงเชื่อมกันทันที

```
เว็บลูกค้า  ninhub-shop  ─┐
                          ├─→ Supabase (lpezkbshtubprljdyikq)
เว็บสต๊อก  ninhub        ─┘
```

### เปิดระบบจองครั้งแรก

Supabase → **SQL Editor** → รันไฟล์ **`supabase/reservations.sql`** (รันซ้ำได้ ไม่ลบข้อมูล)

ไฟล์นี้สร้าง:
- ตาราง `public.reservations` เก็บ ชื่อ / เบอร์ / สินค้า / จำนวน / วันที่รับ / หมายเหตุ / สถานะ
- RLS: **anon อ่านตารางไม่ได้** (กันข้อมูลลูกค้ารั่ว) · แอดมินอ่าน/อัปเดต/ลบได้ตาม `public.is_admin()`
- `create_reservation()` สำหรับเว็บลูกค้าจอง (ตรวจข้อมูลฝั่งเซิร์ฟเวอร์ + กันกดซ้ำ 10 นาที)
- `reservation_lookup(phone)` ให้ลูกค้าตรวจสอบการจองของตัวเองด้วยเบอร์โทร

### จัดการการจองในเว็บสต๊อก

แอดมิน → เมนู **📋 การจอง** → เห็นตัวเลขรอยืนยัน/ยืนยันแล้ว/รับแล้ว/ยกเลิก, ค้นหา, กรองสถานะ และกดเปลี่ยนสถานะได้

| สถานะ | ความหมาย | ปุ่มในหลังบ้าน |
|---|---|---|
| `pending` | ลูกค้าจองเข้ามาใหม่ | ✓ ยืนยัน / ยกเลิก |
| `confirmed` | ร้านยืนยัน เก็บของให้แล้ว | 📦 รับสินค้าแล้ว / ยกเลิก |
| `completed` | ลูกค้ามารับของแล้ว | 🗑 ลบ |
| `cancelled` | ยกเลิก | 🗑 ลบ |

> **การจองไม่ตัดสต๊อกอัตโนมัติ** — เมื่อลูกค้ามารับสินค้า ให้บันทึกที่หน้า **🧾 ขายสินค้า** ตามปกติ แล้วกลับมากด “รับสินค้าแล้ว” ที่รายการจอง (กันการตัดสต๊อกซ้ำซ้อน)

### เว็บลูกค้า

- repo แยกชื่อ **`ninhub-shop`** (โฟลเดอร์ `ninhub-shop` บนเครื่อง) — มี `index.html`, `js/config.js`, `README.md`
- ใช้ `SUPABASE_URL` + `SUPABASE_ANON_KEY` ชุดเดียวกับ repo นี้
- อ่านสินค้าผ่าน `public_catalog()` เท่านั้น และจองผ่าน `create_reservation()`
- Deploy บน Vercel อีกโปรเจกต์หนึ่ง (Framework = Other, ไม่มี Build Command)
- รายละเอียดทั้งหมดดูใน `README.md` ของ repo `ninhub-shop`

### หลังได้โดเมนใหม่ (ทั้งสองเว็บ)

ไปที่ **Supabase → Authentication → URL Configuration**
- **Site URL:** ลิงก์เว็บสต๊อก
- **Redirect URLs:** เพิ่ม `https://<เว็บสต๊อก>/**` และ `https://<เว็บลูกค้า>/**`
