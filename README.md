# Nintendo Stock Manager (Supabase)

ระบบจัดการสินค้า Nintendo Switch แบบออนไลน์ มีล็อกอิน, สิทธิ์แอดมิน/พนักงาน, เก็บข้อมูลใน Supabase (ฟรี)

## โครงสร้างไฟล์

- `index.html` — แอปหลัก (ล็อกอิน + จัดการคลังสินค้า รับเข้า/ขาย/โอน Excel รายงาน)
- `js/config.js` — ใส่ URL และ anon key ของ Supabase
- `supabase/schema.sql` — ตาราง + สิทธิ์ + ฟังก์ชันบันทึกสต๊อก
- `supabase/upgrade-auto-create.sql` — อัปเกรดฐานข้อมูลเดิมให้รองรับ "สร้างสินค้าใหม่อัตโนมัติ" (วางใน SQL Editor แล้ว Run ได้เลย ไม่ลบข้อมูลเดิม)

## ขั้นตอนตั้งค่า (ครั้งแรก)

### 1. สร้างโปรเจกต์ Supabase (ฟรี)

1. ไปที่ https://supabase.com → สมัครบัญชี → **New Project**
2. ตั้งชื่อโปรเจกต์ เชื่อ region `Southeast Asia (Singapore)` เพื่อความเร็ว
3. ตั้งรหัสฐานข้อมูล (เก็บไว้)

### 2. รัน schema

1. ใน Supabase Dashboard เลือก **SQL Editor** → **New query**
2. เปิดไฟล์ `supabase/schema.sql` คัดลอกทั้งหมดวางลงไป → กด **Run**
3. ตรวจสอบว่าไม่มี error (มีข้อความ success)
4. รันซ้ำได้เสมอ (idempotent) — ถ้าเคยรันเวอร์ชันเก่า ให้วางไฟล์ใหม่ทับแล้ว Run อีกครั้งเพื่ออัปเดตสิทธิ์/ฟังก์ชัน

> หมายเหตุด้านความปลอดภัย: ระบบบังคับที่ database ระดับ RLS — **การบันทึกเคลื่อนไหว (รับเข้า/ขาย/โอน), ปรับยอดตรวจนับ, นำเข้า Excel และเพิ่ม/แก้ไข/ลบสินค้า เป็นสิทธิ์แอดมินคนเดียว** พนักงานดูและส่งออกได้อย่างเดียว

## การออกจากระบบอัตโนมัติ

- **ปิดเบราว์เซอร์/แท็บแล้วเปิดใหม่ → ยังล็อกอินอยู่** (ไม่ต้องเข้าสู่ระบบใหม่ จนกว่าจะกด “ออกจากระบบ” หรือไม่ใช้งานเกิน 5 ชั่วโมง)
- **ไม่มีการใช้งานเกิน 5 ชั่วโมง → ออกจากระบบอัตโนมัติ** และกลับไปหน้าล็อกอิน (นับจากการขยับเมาส์/พิมพ์/แตะ/เลื่อนหน้าจอ; ถ้าเปิดหลายแท็บจะนับรวมกัน)

### 3. เปิดใช้ Realtime (ให้หลายอุปกรณ์อัปเดตพร้อมกัน)

1. ไปที่ **Database** → **Replications**
2. เปิดตาราง `products` และ `moves` (toggle ON)

### 4. ใส่ค่า Supabase ในแอป

1. ไปที่ **Project Settings** → **API** (หรือ **Data API**)
2. คัดลอก **Project URL** และ **anon public key**
3. เปิดไฟล์ `js/config.js` ใส่ค่า:
   ```js
   window.SUPABASE_URL = 'https://xxxx.supabase.co';
   window.SUPABASE_ANON_KEY = 'eyJhbGciOi...';
   ```

### 5. ปิดการยืนยันอีเมล (สำหรับทดสอบง่าย ๆ)

1. ไปที่ **Authentication** → **Sign In / Providers** → **Email**
2. ปิด **Confirm email** (หรือจะเปิดไว้ก็ได้ แล้วกดยืนยันจากอีเมลจริง)

### 6. สมัครสมาชิกและตั้งตัวเองเป็นแอดมิน

1. เปิด `index.html` ในเบราว์เซอร์ (หรือรัน `npx serve` ในโฟลเดอร์นี้)
2. กด **ยังไม่มีบัญชี? สมัครสมาชิก** → ใส่อีเมล+รหัสผ่าน
3. หลังสมัคร กลับไป Supabase → **SQL Editor** รัน:
   ```sql
   update public.profiles set role = 'admin' where email = 'YOUR_EMAIL@example.com';
   ```
4. ออกจากระบบแล้วเข้าใหม่ → ตอนนี้เป็นแอดมินแล้ว

## วิธีรันในเครื่อง

```bash
# ในโฟลเดอร์โปรเจกต์
npx serve .
# หรือถ้ามี Python
python -m http.server 8000
```

เปิด `http://localhost:3000` (หรือพอร์ตที่ `serve` แจ้ง)

## การจัดการคลังสินค้า

- **การ์ด “⚠️ สินค้าใกล้หมด” กดได้** — แสดงจำนวนแยก “เหลือ 0” กับ “เหลือ 1–3” และเมื่อกดจะเปิดหน้าคลังสินค้าที่กรองเฉพาะสินค้าใกล้หมด **เรียงจากน้อยไปมาก (ของที่หมด/ติดลบขึ้นก่อน)** พร้อมคอลัมน์ “คงเหลือ” และป้ายสีแดงสำหรับของที่หมดแล้ว — มีปุ่ม **⚠️ ใกล้หมด** ไว้เปิด/ปิดตัวกรองเอง
- **กราฟสินค้าขายดี** — หน้าภาพรวมมีกราฟแท่ง “🏆 สินค้าขายดี” 10 อันดับแรก สลับดูได้ **วันนี้ / เดือนนี้ / ปีนี้** พร้อมยอดขาย (ชิ้น) และมูลค่ารวมของช่วงนั้น (นับเฉพาะรายการ “ขายออก”)
- **เลือกหลายรายการ** (ติ๊กช่องหน้าตาราง) แล้วกด **📁 ย้ายหมวดหมู่** เพื่อย้ายสินค้าที่เลือกไปหมวดที่ต้องการพร้อมกัน หรือกด **🗑 ลบที่เลือก** เพื่อลบทั้งชุด
- **แบ่งหน้า** — เลือก “แสดงต่อหน้า” 20 / 50 / 100 / ทั้งหมด หรือกดเลขหน้า / ก่อนหน้า–ถัดไป ใต้ตาราง (ค่าเริ่มต้น 50 รายการ)
- **สแกนหาสินค้า** — กดปุ่ม **▦ สแกน** มุมขวาบน ระบบจะเปิดกล้องแล้วค้นหาสินค้าจากบาร์โค้ดให้ทันที (เปิดหน้ารายละเอียดให้) หรือใช้เครื่องสแกนยิงเข้าช่องค้นหาแล้วกด Enter ก็ได้
- ช่อง “เลือกทั้งหมด” จะเลือกเฉพาะรายการในหน้านี้

## การขายหลายรายการในบิลเดียว

1. ไปที่หน้า **บันทึกสินค้าเคลื่อนไหว** แล้วเลือกแท็บ **ขายสินค้า**
2. สแกน/พิมพ์รหัสหรือเลือกสินค้า ใส่จำนวนและราคา แล้วกด **＋ เพิ่มลงบิล** (ทำซ้ำได้หลายรายการ)
3. ตรวจรายการในบิล (รหัสซ้ำจะรวมจำนวนให้อัตโนมัติ) แล้วกด **💾 บันทึกบิล** — ระบบจะตัดสต๊อกทุกรายการพร้อมกันในครั้งเดียว
4. หลังบันทึกบิลจะเคลียร์รายการให้เริ่มบิลใหม่ทันที (บิลก่อนหน้าถูกเก็บไว้แล้ว)
5. ตาราง **บิลขายล่าสุด** ด้านล่างแสดงเลขบิล จำนวนรายการ ชิ้น และยอดรวม — กด **ดู** เพื่อเปิดรายละเอียดว่าบิลนั้นขายอะไรไปบ้าง
6. **ยกเลิกบิลได้ภายใน 24 ชั่วโมง** (เฉพาะแอดมิน) — กดปุ่ม **ยกเลิก** ในตารางหรือในหน้าต่างรายละเอียดบิล ระบบจะคืนจำนวนสินค้าเข้าคลังและลบรายการขายของบิลนั้นออกจากประวัติ (เกิน 24 ชม. ปุ่มจะหายไป และเซิร์ฟเวอร์ก็ปฏิเสธ)

> การขายหนึ่งครั้งได้เลขบิล (`bill_id`) เดียวกันทุกรายการ และประวัติ/ไฟล์ส่งออก Excel มีคอลัมน์ **เลขบิล** ให้ด้วย รายการขายเก่าก่อนอัปเดตจะแสดงเป็น “บิลเดี่ยว”
> ต้องรัน `supabase/upgrade-auto-create.sql` อีกครั้งเพื่อเพิ่มคอลัมน์ `bill_id` และฟังก์ชัน `record_bill`
> ต้องรัน `supabase/cancel-bill.sql` หนึ่งครั้งเพื่อเปิดใช้ฟังก์ชัน `cancel_sale` (ยกเลิกบิล)

## การนำเข้าข้อมูล (ไฟล์ Excel)

**รหัสที่ยังไม่มีในคลังจะถูกสร้างสินค้าใหม่อัตโนมัติในหมวด “ไม่มีหมวดหมู่” เสมอ** (เฉพาะสิทธิ์แอดมิน) และจะมีหน้าตารางยืนยันให้ตรวจสอบก่อนทุกครั้ง

พฤติกรรมเมื่อยืนยันนำเข้า:

- **สินค้าใหม่ (รหัสยังไม่มีในระบบ)** → สร้างในหมวด `ไม่มีหมวดหมู่` พร้อมจำนวน/บาร์โค้ด/ราคาจากไฟล์ แล้วค่อยย้ายหมวดทีหลังได้
- **สินค้าที่มีอยู่แล้ว (โหมดบวกจำนวน – ค่าเริ่มต้น)** → บวกจำนวนจากไฟล์เข้าสต๊อก และบันทึก movement `รับเข้า`
- **จำนวนคงเดิม** → ถ้าจำนวนในไฟล์เท่ากับจำนวนในระบบ (หรือเป็น 0) จะ **ไม่บวกซ้ำ** และไม่สร้าง movement (อัปเดตเฉพาะบาร์โค้ด/ราคาที่มีใหม่)
- **อัปเดตเฉพาะบาร์โค้ด/ราคา** → โหมดสำหรับเติมบาร์โค้ดให้สินค้าเดิมโดยไม่แตะจำนวนสต๊อก (ใช้เมื่อบาร์โค้ดในระบบยังว่าง)
- ถ้าต้องการปรับยอดให้ตรงกับการนับจริง ใช้โหมด **ปรับยอดคงเหลือให้ตรงกับจำนวนที่นับ**

> ไฟล์ Excel ของบริษัท (`PRNDATE | SKCODE | IBC | SBC | PRNAME | QUANT | RETAIL`) ใช้ได้โดยตรง: รหัสสินค้า = `SKCODE`, บาร์โค้ด = `SBC` ถ้าว่างจะใช้ `IBC` แทน, จำนวน = `QUANT`, ราคา = `RETAIL`

> ถ้าเคยรันสคริปต์เวอร์ชันเก่าไว้ ให้รัน `supabase/upgrade-auto-create.sql` อีกครั้ง (Supabase → SQL Editor → วางทั้งไฟล์ → Run)
> เพื่ออัปเดตฟังก์ชัน `apply_stock_count` ให้สร้างสินค้าใหม่ + บันทึก movement ได้ครบทุกโหมด
> ไฟล์นี้ยังย้ายสินค้าที่มีชื่อหมวดหมู่นอกเหนือจากรายการหลัก (เช่น `เครื่อง`, `JOY&ACC` ที่ติดมาจาก Excel) ไปเป็น `ไม่มีหมวดหมู่` ให้ด้วย

### นำเข้าไฟล์ Excel

1. ไปที่หน้า **Excel นำเข้า–ส่งออก**
2. อัปโหลดไฟล์ `.xlsx` / `.xls` / `.csv`
3. ระบบจะหาแถวหัวตารางและคอลัมน์ **รหัสสินค้า** + **จำนวน** ให้เอง (รองรับหัวตารางไทย/อังกฤษ, มีแถวหัวเรื่องนำหน้า, จำนวนเป็นข้อความมีหน่วย เช่น `10 ชิ้น` หรือมีคอมม่า `1,250`)
4. ตรวจสอบตาราง "สถานะ" แล้วกด **ยืนยันนำเข้าข้อมูล**

ชื่อสินค้า / **บาร์โค้ด** / **ราคา** ใส่ได้ถ้ามี (ไม่บังคับ) และจะถูกบันทึกเข้าคลังให้อัตโนมัติ — คอลัมน์หมวดหมู่ในไฟล์จะไม่ถูกใช้ (สินค้าใหม่ลง `ไม่มีหมวดหมู่` เสมอ)

**รองรับรายงาน POS โดยตรง** — ถ้าหัวตารางเป็น
`PRNDATE | SKCODE (SBC) | PRNAME | QUANT | RETAIL` ระบบจะจับคอลัมน์ถูกเอง
(คอลัมน์ `SKCODE`/`SBC` → รหัสสินค้า, `PRNAME` → ชื่อ, `QUANT` → จำนวน, `SBC`/บาร์โค้ด → บาร์โค้ด, `RETAIL`/ราคา → ราคา/ต้นทุนต่อชิ้น)
แถวตัวอย่าง: `17/10/2026 19:55:10 | 306200 | 4902370553208 | NS-JOY-CON2 NINTENDO-WHEEL-SET | 1.00 | 790.00`

> คอลัมน์บาร์โค้ดต้องมีค่าเต็ม 13 หลัก ถ้าใน Excel แสดงเป็น `4.90237E+12` ให้ขยายคอลัมน์/ตั้งรูปแบบเป็น Text ก่อนบันทึก ไม่งั้นตัวเลขจะถูกปัดหาย
> ตัวอ่านไฟล์ Excel ( SheetJS ) จะโหลดเมื่อเปิดเมนู **Excel นำเข้า–ส่งออก** ครั้งแรก ไม่ถ่วงเวลาเข้าสู่ระบบ

กฎความปลอดภัยของตัวนำเข้า:

- **จำนวนต้องเป็นจำนวนเต็ม ≥ 0** — ถ้าเป็นทศนิยม (เช่น `1.50`) จะขึ้นสถานะ `จำนวนต้องเป็นจำนวนเต็ม` และบล็อกการนำเข้าจนกว่าจะแก้
- รหัสซ้ำในไฟล์เดียวกัน → บล็อกการนำเข้า
- จำนวนที่ผิดปกติ (เช่น > 999,999 ซึ่งน่าจะเป็นบาร์โค้ดที่อ่านเพี้ยน) → ขึ้นสถานะ `จำนวนผิดปกติ` และบล็อกการนำเข้า
- จำนวนที่มีเครื่องหมายคอมม่า หรือสูงผิดปกติ → ขึ้นป้าย `ควรตรวจสอบ` (ไม่บล็อก แต่ให้เช็กก่อนยืนยัน)
- ถ้าไฟล์ไม่มีคอลัมน์รหัสสินค้า ระบบจะหาสินค้าในคลังจาก **ชื่อสินค้า** ให้อัตโนมัติ (ต้องให้ชื่อตรงกับข้อมูลในระบบ) แล้วขึ้นป้าย `จับคู่จากชื่อสินค้า`

### ส่งออก Excel

เลือก “ชนิดข้อมูล” ได้: **สินค้าคงเหลือปัจจุบัน**, **ประวัติรับเข้า–ขาย–โอน** (ทั้งหมด — ตัวเลือกเดิม), หรือแยกเป็น **ประวัติรับเข้า**, **ประวัติขาย**, **ประวัติโอน** ตามหมวดหมู่ที่เลือก

## ลดปริมาณการใช้งาน Supabase (Free plan)

โควตาฟรีที่มักเต็มก่อน: **Egress 5 GB/เดือน** และ **Database 500 MB** (รูปสินค้าเก็บเป็น base64 ในฐานข้อมูล)

สิ่งที่ปรับไว้ให้แล้ว:

- **รูปย่ออัตโนมัติก่อนบันทึก** — ย่อด้านยาวสุดไม่เกิน 640 px เป็น JPEG คุณภาพ 0.62 (รูปจากกล้องมือถือหลาย MB จะเหลือไม่กี่สิบ KB) และรับไฟล์ได้ไม่เกิน 8 MB
- **ไม่โหลดรูปทั้งคลังตอนเข้าเว็บ** — แกลเลอรีโหลดรูปเฉพาะการ์ดที่เลื่อนมาเห็น (IntersectionObserver) และรวมคำขอเป็นชุด (batched)
- **แคชรูปในเครื่อง (IndexedDB)** — เปิดรูปเดิมซ้ำในเครื่อง/เบราว์เซอร์เดิม = โหลดจากเครื่อง ไม่กิน egress และตัดแคชอัตโนมัติเมื่อแก้รูป (อิง `updated_at`)
- **ประวัติเคลื่อนไหวโหลดแค่ 200 รายการล่าสุด** และเฉพาะคอลัมน์ที่ใช้ (จากเดิม 500 แถวทั้งตาราง)
- **แคตตาล็อก** จะโหลดรูปของหมวดที่เลือกครั้งเดียวตอนสั่งพิมพ์ และมีคำเตือนถ้าเกิน 40 รายการ — ใช้เมื่อจำเป็นเท่านั้น
- **บีบอัดรูปเก่าทั้งคลัง (เฉพาะแอดมิน)** — เมนูด้านซ้าย “🧹 บีบอัดรูป” กดครั้งเดียวระบบจะย่อรูปเดิมทีละชุดแล้วบันทึกทับด้วยรูป 640 px / คุณภาพ 0.6 พร้อมแจ้งความคืบหน้าและสรุปขนาดก่อน–หลัง (แนะนำให้รันหนึ่งครั้งหลังอัปเดตระบบ)

คำแนะนำเพิ่มเติม:

- หลีกเลี่ยงการอัปโหลดรูปความละเอียดสูงซ้ำ ๆ ระบบย่อให้แล้ว — รูปเก่าที่เคยบันทึกไว้ให้ใช้การ์ด “บีบอัดรูปสินค้าเก่า” (กินเน็ตครั้งเดียวตอนรัน แต่ลดขนาดถาวร) หรือลบ/เปลี่ยนรูปที่ไม่ใช้
- Egress นับเฉพาะข้อมูลที่โหลดผ่านอินเทอร์เน็ต (รวมรูปที่เปิดดู) — ถ้าเดือนไหนใกล้เต็ม ให้ลดการเปิดแคตตาล็อก/แกลเลอรีรูปจำนวนมาก
- ดูขนาดรูปที่เก็บอยู่ได้ด้วย SQL:
  ```sql
  select count(*) filter (where image <> '') as with_image,
         pg_size_pretty(sum(pg_column_size(image))::bigint) as total_image,
         pg_size_pretty((avg(pg_column_size(image)) filter (where image <> ''))::bigint) as avg_image
  from public.products;
  ```
- โควตาจะรีเซ็ตรอบบิลรายเดือนใน Supabase → Settings → Billing

## สิทธิ์ผู้ใช้

| หน้าที่ | แอดมิน | พนักงาน |
|--------|--------|---------|
| ดูสินค้า/รายงาน | ✓ | ✓ |
| บันทึกรับเข้า / ขาย / โอน | ✓ | ✗ |
| เพิ่ม/แก้ไข/ลบสินค้า | ✓ | ✗ |
| นำเข้า Excel ปรับสต๊อก | ✓ | ✗ |
| ส่งออก Excel | ✓ | ✓ |

ผู้ใช้ใหม่ที่สมัครจะได้เป็น `staff` (พนักงาน) อัตโนมัติ

> พนักงานดูสต๊อก/รายงานและส่งออก Excel ได้เท่านั้น — เมนู “รับเข้า / ขาย / โอน” จะถูกซ่อน และฐานข้อมูลจะปฏิเสธถ้าพนักงานเรียก RPC ตรง ๆ (ต้องรัน `supabase/restrict-moves-admin.sql` ใน Supabase SQL Editor หนึ่งครั้ง)

## ขึ้นเว็บจริง (ภายหลัง)

เนื่องจากเป็น static files + Supabase (backend สำเร็จรูป) สามารถ deploy ขึ้นได้เลย เช่น

- **Vercel** / **Netlify** / **Cloudflare Pages** — ลากโฟลเดอร์ไป deploy ฟรี
- หรือ host บนเซิร์ฟเวอร์ตัวเองด้วย nginx/caddy

ไม่ต้องเขียน backend เพิ่ม Supabase ทำหน้าที่เป็น backend ให้แล้ว

## ข้อควรระวัง

- `SUPABASE_ANON_KEY` เป็นของสาธารณะ (ปลอดภัยที่จะใส่ในหน้าเว็บ) เพราะ RLS จะตรวจสิทธิ์ทุกครั้ง
- **ห้าม** ใช้ `service_role` key ในหน้าเว็บเด็ดขาด
- ถ้าเปลี่ยนรหัสผ่าน Supabase หรือลบโปรเจกต์ ต้องอัปเดต `js/config.js` ใหม่
